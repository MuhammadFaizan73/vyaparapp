Brief

One ledger, two front doors

Pakistani shopkeepers run their business from two devices at once: a desktop at the counter for billing, and a phone in the pocket for the road. Vyapar Pakistan was commissioned to serve both from a single source of truth — a shopkeeper enters a sale on the phone during a delivery run and sees it reflected on the desktop register by the time they're back at the shop.

The build was scoped under an exclusive-distribution licensing agreement, with a fixed list of contractual features (company-isolated invoicing, a GPS-tracked salesman module, Excel-to-form paste, bilingual voice entry, tiered subscriptions) that had to ship alongside the core accounting workflows. That contract is the scorecard used later in this document.

Architecture

Shared backend, native front ends

Both clients talk to the same NestJS API over HTTP + JWT and never touch the database directly. A tenant is resolved by phone number, not email or device — the same number on Desktop and Mobile resolves to the same company, same items, same ledgers. Two supporting packages keep the clients honest: @vyapar/shared-types (Zod schemas as the API contract) and @vyapar/api-client (the one HTTP layer every UI calls through).

Desktop
Electron · React · Vite

The counter register

Built for the person standing at the shop counter: card-based invoicing rather than a spreadsheet grid, fast keyboard-first data entry, and bulk import for shopkeepers migrating years of ledgers out of Excel.

1renderer, reused by future web client
  • Sale & purchase entryCard-based invoice screen with an Add Items modal, print/PDF preview, and delivery-challan generation — kept deliberately off the spreadsheet-grid pattern common in this category.
  • Excel → form pasteCopy a block of cells from any spreadsheet and paste directly into Items or Parties; a column-mapping modal (ExcelColumnsModal) resolves which column feeds which field.
  • Multi-company isolationItems carry a companyTag; the sale screen, items list, and every report filter by the active company so stock and revenue never cross-contaminate.
  • Cash, bank & loansDedicated Cash-in-Hand, Bank Accounts, and Loan Account screens sit alongside the transaction ledger, not bolted on as an afterthought.
  • Licensing & syncOnboarding, license-gate, activation-modal, and a Sync/Share screen mirror the same trial → license flow that governs Mobile.
Mobile
Expo · React Native

The one in your pocket

Mobile carries the full transaction lifecycle plus everything that only makes sense in the field: salesman GPS tracking, weekly shop assignments, and device-session control for a team sharing one license.

12transaction types covered
  • Full transaction setSale, purchase, sale/purchase orders, sale/purchase returns, credit/debit notes, delivery notes, estimates, and proforma invoices — each with its own list + form pair.
  • Salesman GPS moduleWeekly shop assignments surface automatically on login; live location pings and check-in/check-out logs (ShopVisit, LocationPing) record which shops were actually visited and what was sold there.
  • Team & device controlRole-based staff invites, a single-active-device policy per license, and a device-session manager so a shared license can't be logged into indefinitely many phones at once.
  • Voice-assisted searchA mic button on the Sale screen drives voice search over the transaction list via @react-native-voice/voice, with a text-search fallback when the native module isn't available (e.g. Expo Go).
  • Party & location toolsCustomer/party creation with a map-based location picker, phone-contact import, and party statements — built for a salesperson who's standing in front of the shop, not at a desk.
